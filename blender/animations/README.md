# Shared party animation source

`party.blend` is the original accepted humanoid motion library, promoted from the [saved party study](../studies/party-characters/README.md) on 24 November 2026. Codex authored the source for Lauder in Blender 5.3; no third-party rig, animation or texture was imported. The repository's [MIT licence](../../LICENSE) applies. The editable binary uses Git LFS.

The file owns the shared 17-bone `Party humanoid skeleton`, eleven preserved `party.<clip>` source Actions and a derived one-cycle `party.runtime` preview. Canonical [Miki](../assets/miki/README.md), [Laura](../assets/laura/README.md) and [Tom](../assets/tom/README.md) link the same skeleton and Actions into independent local rig Objects. Their geometry and skin weights stay in their own canonical files. No review floor, camera, lighting, labels or weapon proxies enter this library or its exports.

Edit the shared source Actions here rather than making per-character copies. Keep baked linear joint keys, quaternion rotation mode, frame 1 start, integer end frames and metre scale. The Armature's `lauder_party_animation` JSON custom property declares the source Action names, loop intent, nominal travel speed and 120 fps; actual Action bounds determine clip lengths and timeline offsets. Each reaction may declare `event_start` in local clip seconds (fire 0.10, hit 0.08); other clips use zero. Export validates the offset and generates `Take.eventStart`, allowing an accepted gameplay event to skip the source review anticipation without changing the authored curves or scheduling gameplay from animation. The eleven Actions cover idle, walk, jog, backward, both strafes, aim, fire, hit, run and sneak. The run and sneak Actions are original additions assigned on 24 November; the nine accepted study Actions are preserved exactly. Run has a 0.65-second cycle at a nominal 2.711 m/s, while sneak has a 1.2-second cycle at 0.429 m/s with at least one planted foot. They were authored at 480 Hz; the registered USD export samples the common 120-fps timeline, which is validated independently after import. ROOT is nondeforming, with vertical compression and no horizontal motion. Do not rename or change the rest hierarchy without updating its runtime bindings.

Every party model export builds a fresh one-cycle scratch timeline from those saved source Actions, so edited motion reaches every figure without a private animation generator or separately maintained timing constants. It exports the skinned skeleton, explicitly preserves the final held USD sample, and packages USDZ. Saving this exact shared library queues the three ordinary model exports in order; the Lauder tab's Export button also refreshes them. For a headless shared edit, run `blender/scripts/export-model.py -- miki`, then `-- laura` and `-- tom` in background Blender. Miki owns the one generated `apple/sources/content/PartyModelClips.swift` output. The normal export ledger fingerprints the shared library and generator for all three models; `./scripts/check` rejects stale outputs.

The retained `party.runtime` timeline is an editing preview, derived from the source Actions. Runtime export always rebuilds it rather than treating preview cuts as gameplay transitions. Animation is presentation: movement, navigation, weapons and damage remain owned by the game simulation.

The [run/sneak motion reel](run-sneak-preview.mp4) shows the actual three meshes with four running cycles followed by three sneaking cycles. Codex rendered it from these original Actions in Blender: 980 × 702, H.264, 30 fps, 187 decoded frames and 6.23 seconds, in real time. The labelled cut separates the takes. This MIT review video uses an explicit Git LFS rule and is outside app resources; it demonstrates source motion rather than runtime blending, weapon contact or phone performance.
